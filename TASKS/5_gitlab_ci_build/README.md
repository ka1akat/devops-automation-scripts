# Task 5 — простой build-пайплайн

## Задание
Создать `.gitlab-ci.yml` с одним этапом `build` и одной задачей,
которая печатает два сообщения. Сделать push и убедиться, что пайплайн зелёный.

## Файл
```yaml
stages:
  - build

build_job:
  stage: build
  script:
    - echo "Building the project..."
    - echo "This is a basic build job."
```

## Что значит каждая строка
- `stages:` — список этапов и их порядок. Пишется один раз в начале файла.
- `- build` — единственный этап.
- `build_job:` — имя задачи (job). Придумываю сама.
- `stage: build` — к какому этапу относится задача. Должно быть из списка `stages`.
- `script:` — команды, которые выполнит runner, сверху вниз.
- `- echo "..."` — обычная команда Linux, просто печатает текст.

## Главное, что я поняла
- CI/CD — робот, который после каждого `git push` сам выполняет инструкцию из `.gitlab-ci.yml`.
- В одном репозитории работает только один `.gitlab-ci.yml`, в корне.
- **Pipeline** — вся работа после одного push. **Stage** — этап (идут по порядку). **Job** — конкретная работа с командами.
- Если этап упал, следующие этапы не запускаются.
- Выполняет **runner**: для каждого job создаёт чистый Docker-контейнер → скачивает код → выполняет `script` → удаляет контейнер.
- Каждый job начинается с нуля, файлы из одного job не видны в другом.

## Мои ошибки
- Написала `- echo:` с двоеточием — неправильно, `echo` — команда, двоеточие не нужно.
- `cat gitlab-ci.yml` без точки — файл называется `.gitlab-ci.yml`.
- В nano неудобно ставить отступы → пишу YAML в VS Code.
